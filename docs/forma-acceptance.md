# Arca Forma 1.3 对齐记录

本次控制台版本：0.4.0。规范核对日期：2026-11-18。

## 规范与依赖

- [Rosemary Forma 门户](https://design.cruty.cn/)：Forma 1.3.0。
- [官方 SDK v0.5.0](https://github.com/Foodie05/Rosemary-Design-System/releases/tag/v0.5.0)：React、tokens、icons 三个发布包原样保存在 `web/vendor/rosemary`，逐个通过发布方 SHA256SUMS 校验。

## 验证方式

```sh
cd web
pnpm install --frozen-lockfile
pnpm build
pnpm exec playwright install chromium
pnpm test:ui
```

浏览器使用本地合成 API fixture，不读取生产凭据，也不删除真实桶。测试覆盖八个页面的明暗主题与 axe WCAG A/AA、320/390/768px 窄屏、系统外观变化、减少动态、强制颜色模拟、抽屉中断、存储源风险与重验、删除桶两阶段保护、下载签名参数、浏览器历史及登录/OOBE。CI 使用相同构建和 Chromium 测试。

Go 全套 `go test ./...` 通过，新增上传邀请的权限、数量、覆盖、幂等和桶删除关联清理测试均通过。

## 独立 Luna 审查

按用户要求启动独立 `gpt-6-luna`，未传递主代理的推理历史。审查者自行读取正式规范、实现、SDK CSS、移动端及深色截图，并独立运行当时的 8 项 UI 测试（8/8 通过，24.9 秒）。未报告可复现 P1/P2/P3 问题。

主代理在实现与初轮验收中修正了：系统主题按钮目标名称不一致；完成动画留下 transform；代码滚动区无法键盘聚焦；异步读取后编辑入口焦点丢失；未完成操作被浏览器返回丢弃；请求中字段可变；已生成 Agent 授权与可编辑条件不一致；强制颜色检查中复选框装饰层阻挡原生命中区域。

最终增量已由同一独立 Luna 再次静态复核：确认请求字段冻结、OOBE 返回保护、Agent 授权条件冻结、复选框命中修复未引入可复现体验问题。新增系统偏好、强制颜色与抽屉中断测试已单项通过；后续合并线上功能后，最终完整 13 项 UI 测试全部通过。

## 验证边界

Chromium 自动化及 axe 不等于人工可访问性认证。真实 Safari/WebKit、真实触屏设备、VoiceOver/NVDA、物理高对比显示环境仍需单独验收。截图保存在本地忽略目录 `.local/forma-qa`，全部使用演示数据。

合并线上功能时，依据实际部署的 `0.3.5-arca.20261015.6cbda647` 文档、前端产物、后端符号、SQLite 表结构和隔离的旧/新二进制协议测试补齐源码。线上源码补丁未保存，因此这次是依据运行契约恢复能力，而不是直接套用一个现成 Git 补丁。

服务器上使用一次性受保护的 SQLite 副本运行兼容测试：原有所有表逐行摘要保持不变，5 份上传授权与 25 条上传回执可正常读取，quick_check 与 foreign_key_check 均通过。测试没有读取或复制凭据到本地，也没有在生产数据库上运行迁移预检。

生产部署结果以部署清单和线上 `/api/v1/version` 为准。

合并后的独立 Luna 复审发现并修复一项 P3：切换桶时旧的授权列表请求可能覆盖当前列表。所有读取请求共用 generation 检查；切桶清空列表并使旧请求失效，BucketManager 按桶名设置组件 key。新增延迟响应回归测试覆盖“先返回 B，再返回 A”的顺序。Luna 已静态复核最终修复，未发现新增问题。

使用隔离数据库和回环 S3 stub 执行 `scripts/compare-release-contract.py`，对照线上旧二进制与合并后二进制的公开/私有桶流程：授权字段、签名状态与字段、上传→commit→重复提交、公开别名、禁止覆盖、数量上限和撤销后拒绝提交。保留线上 201 签名响应、expected_size 与公开别名 600 秒回源签名周期。普通应用按次请求的有效期仍完全由应用提供。
